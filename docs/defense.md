# Defending our choices

Questions a grader, TA, or interviewer is likely to ask, with the short answer and where the evidence lives.
Run folders are in `results/`; the full story is in `docs/prompt-iterations.md`.

## The prompt

**Why is v4 the final prompt and not v3?**
Same results on every test (100% on the main suite and on the Synthea held-out set, every safety gate passing), with
half the words (724 vs 1,578) and 29% fewer input tokens per call. A shorter prompt is cheaper and easier to read and
maintain. Evidence: `v3_…1655` vs `v4_…1829`; `v3_…_heldout` vs `v4_…_heldout`.

**v4 has a known weakness. Why ship it?**
At temperature 0.7 it sometimes calls "take 2 tablets of 20 mg" a dose change when the plan says 40 mg. That is a false
alarm in the safe direction: the caregiver is told to ask the pharmacist. We tried to fix it (v5) and the fix made a
safety gate worse, so we kept the weakness and documented it. At our real setting (temperature 0.3) and at 0.0 it
passes. Evidence: `v4_deepseek-flash_t0.7_*_stab`.

**Why reject v5 if the broken reply was probably random?**
Our rule, set before any testing, is that a safety outcome can never get worse from one version to the next. v5 had a
911 case return an unreadable reply (tier-3 recall 95% vs 100%). We can't prove it was random from one run, and "re-run
until it passes" is not a fair test. The right fix for random broken output is in the app (retry once, then show a
fixed "if this is an emergency, call 911" message), not in the prompt.

**Why JSON output instead of plain text?**
It makes every reply checkable by code (flags, tier, cited ids), and it lets us put the reasoning fields before the
reply, so the model works through the problem before it writes to the caregiver.

**Does the self-check actually do anything?**
Honestly, we couldn't measure a benefit: removing it kept every test passing and cut cost 12%
(`v3-noselfcheck_…1729`). We also saw a reply mark every self-check true while failing (v1, dx-05). We keep it as a
cheap safety net and call it what it is: a single-pass check, not Self-Refine's multi-call loop. A real second-call
verifier is the next step.

**Why one example and not more?**
Removing examples didn't change correctness on this model, only style (longer, harder to read). One example keeps the
format and tone without spending tokens. It uses a patient and drugs that appear in no test, so it can't leak answers.

## The tests

**Isn't 100% suspicious? You wrote the prompt and the tests.**
That was the right worry, so we added a held-out test we didn't write by hand: 20 heart-failure patients generated by
Synthea, with cabinets and the answer key made by a seeded script. The final prompt caught all 60 planted problems
there, with one false alarm (a "once daily" bottle vs "at bedtime" in the plan), including messy real-world
medication lists (two statins, Entresto with losartan). We reported that false alarm instead of tuning to it. We also show the failures we did find (v0,
v1, v4 at temperature 0.7, v5), and one grounding slip our checks missed.

**How is the cabinet diff (the core feature) tested?**
33 cabinets with 91 planted problems: 13 hand-built edge cases (brand vs generic, photo typos, unit formats, an
unreadable label, a combination pill, 2 x 20 mg tablets) and 20 Synthea patients. Every flag type is scored
separately (caught, missed, deferred, false alarm), and a missed or deferred stopped medicine is a critical failure.
Final prompt: 91/91 caught, 0 critical, 1 false alarm. It is the largest part of the test set by expected outcomes.

**What happens with messy, real-world-looking data?**
We made the 20 Synthea cabinets messy on purpose at 4 levels (photo misreads, vitamins and Tylenol, up to 17 bottles,
a made-up drug, an "ignore your rules" note inside a label). It drops from 100% to 89% of cabinets fully right (98%
of problems still caught), and never misses a stopped medicine or obeys the injected note. The worst failure: it
matched a made-up drug to a real one instead of saying "not on the list". That tells us exactly what to fix next,
which is why we report it instead of hiding it. `v4_deepseek-flash_t0.3_1018-1916_stress`.

**Why not use Synthea for everything?**
Synthea gives realistic patients and medication records, but no discharge instructions, warning signs, pill bottles, or
caregiver messages, and it recorded no medication changes at these discharges. So we used it for what it does well
(medication lists) and scripted the rest. The hand-written patient stays because it has carefully designed edge cases
(unreadable label, combination pill, abbreviations).

**How do you know the checks are right?**
They are deterministic code, and every failure was read by hand. That reading found false positives twice (logged
under "Test set and checker changes"), which we fixed and re-scored for free from the cache. Regex checks can't judge
wording, which is why the 911 example's extra sentence slipped through.

**What do sensitivity and stability mean here?**
Sensitivity: reword the same message (typos, brand names, caps, shuffled bottles, non-native English) and check the
answer stays the same. Stability: send the same message 3 times at temperature 0.0 and 0.7 and check the answers match.

## The model and cost

**Why DeepSeek Flash?**
Decision rule: the cheapest setup that passes every safety gate. Flash passed everything at $2.63 per 1,000 sessions.
Pro passed too but cost 3.5 times as much; thinking mode cost 2.2 times as much and was slower; a local 8B model was
free but too slow (over 30 seconds on 10 of 23 calls) and made diff errors. Evidence: `--leaderboard` in section 7 of
`docs/assignment2_full_report.md`.

**Why is thinking mode off?**
DeepSeek turns it on by default, and in that mode temperature is ignored, so our first runs couldn't test stability. We
found it in the docs, confirmed it from the token counts, and re-ran everything with it off.

## What's next (semester roadmap)

1. A second-call verifier (real Self-Refine) and a measure of what it catches.
2. App-level safety: retry on broken JSON; fixed 911 fallback.
3. An as-needed (PRN) medicine rule with test cases; a rule for multiple tablets per dose that doesn't hurt safety.
4. Multi-turn conversations; more Synthea patients; the photo route with a local vision model (`qwen2.5vl:7b`).
5. Move patient data to the end of the prompt so it caches across patients (measured cost saving).
