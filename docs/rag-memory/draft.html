2Knowledge sources and RAG

The care plan (~1,500 tokens) and cabinet check are small and always relevant: in the prompt every turn (cache-augmented generation, CAG: no search needed). FDA labels are large and one section matters per question: retrieved from openFDA [1][2]. RxNorm [3], NLM's standard drug-name list, names drugs; NLM retired its interaction API [3], so interactions come from labels.

Only medicine questions retrieve (never 911 cases, dose questions, or small talk): (1) name check against the patient's list, then exact RxNav; no match → pharmacist_check ("ask the pharmacist"); (2) filter to her active medicines and drugs named; (3) add label words ("itchy" → pruritus), hybrid search (BM25 keyword match + vectors that match meaning), top 3; (4) skip if a reranker (a second model that re-scores the matches) is unsure; (5) pass them in a new {{references}} slot with label id and date. Prompt B v8 says "the label says [ref-1]", trusts plan over label over memory, else names the pharmacy.

3Memory

Short-term. Four ways to carry an 11-turn chat (6 scored facts), confirmed on a held-out chat (written after the choice, never used to choose):

Approach Safety facts kept (dev / held-out) Other facts Size
Last 3 or 5 turns 1–2 / 1 of 3 1 / 1 of 3 35–55 words
80-word summary 3 / 3 of 3 2 / 1 of 3 ~70 words
Structured record 3 / 3 of 3 3 / 3 of 3 ~260 words

Windows dropped warning signs; summaries blurred times (though they kept all facts on two 20-turn chats). The record fills a new {{memory}} slot each turn: exact ids and sources, no small talk, flags closed only on evidence; caregiver-reported changes stay questions, never plan edits.

Long-term: semantic (confirmed medicines, schedule), episodic (weight log, past flags, rechecks), procedural (reply preferences); confirmed writes only; view, edit, delete; deleted at day 60 (30-day program + 30 to decide). In two new-session tests, v8 raised every saved follow-up in all 3 runs; the baseline raised none. A resolved flag also updates the cabinet check, so it never comes back.

5Data, compliance, and risks

The class build uses synthetic data only. A parent's medicines and symptoms are likely not PHI (health data HIPAA protects) when the family adopts the app directly [4], but just as sensitive; a hospital deployment needs BAAs (HIPAA contracts), hosting and model providers included [5]. The FTC Health Breach Notification Rule likely applies; unauthorized sharing is a breach [6]. Washington and Nevada require opt-in consent and deletion on request; Connecticut bars selling consumer health data without consent [7–9]. DeepSeek stores data in China [10]: real data needs a self-hosted or BAA-covered model.

Access. Each person sees only what their role needs:

Who Sees Can do
Rosa (patient, account owner) everything invite or remove caregivers; export; delete all
Maria (primary caregiver, invited by Rosa) plan, cabinet check, chat, memory confirm, edit, or delete memory entries
Other family (invited) plan and open items read only
Clinic (hospital deployment only, under a BAA) a summary Rosa chooses to share read only
Model provider one turn's prompt nothing kept: a requirement for any real deployment (DeepSeek offers no BAA, so: self-hosted)

Controls: a consent screen before the first upload (what is stored, where, for how long); encryption in transit and at rest; an audit log of every view, edit, and export; every memory entry shows its source and date and can be deleted on its own; everything is deleted at day 60 unless Rosa renews; a breach means notifying users and the FTC [6].

Risk Mitigation
Wrong, outdated, or invented drug facts Name check; plan or cited, dated label only; stopped drugs only when named
Memory poisoning, injection, staleness Source and date per entry; confirmed writes; documents are data, not instructions
Over-reliance Never diagnose or dose; always name who to call

Limits: retrieval misses 3 of 8 new questions; a borderline breathing sign can be under-triaged (blind set); replies run long; some fixes were picked after seeing results (labelled in the repo).
